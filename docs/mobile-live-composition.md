# Mobile live composition preparation

Source now composes actual device/resource authority, OIDC enrollment, provider custody, PF A/B exchanges, site-scoped document retrieval and a multi-turn Direct Line conversation. Construction opens no listener and rejects simulated leaf adapters. The separately tested HTTPS host binds only `127.0.0.1:9468`; public tunnel routing is not activated.

Provider credentials remain server-side. The explicit mobile OIDC profile requests `openid copilot.login offline_access` with the existing login resource. Its completion hook stores credentials only after the real device signature succeeds. Vault KV-v2 CAS binds the record to original human issuer/subject/audience/authentication time and absolute enrollment expiry. Refresh uses `private_key_jwt`, checks the provider subject/signature/audience/scope/lifetime and requires rotation. It first clears the stored credential into a spent `refreshing` state, so an uncertain response or crash requires sign-in again instead of replay. Resource revocation clears provider credentials from the current Vault record. The mount must retain only one version; storage backups and Microsoft retention are separate controls.

The supported PF profile is explicitly opt-in: the original 60-second phone proof acceptance stays unchanged, while branded internal evidence may have a three-minute execution lease sealed into the device terms. Authority/agent assertions are at most180 seconds, PF A tokens120 seconds and PF B tokens60 seconds, with no child outliving its actual parent. Jobs remain capped at55 seconds. Defaults retain the earlier60-second profile. This change is necessary because read-only inspection of the installed PF JWT manager confirmed integer-minute lifetime parsing; its `exp` fulfillment also represents minutes, not an absolute expiry. This is a new live trust profile requiring approval, not an automatic relaxation of existing deployments. [PF attribute-contract documentation](https://docs.pingidentity.com/pingfederate/13.0/administrators_reference_guide/pf_defining_access_token_attribute_contract.html).

Document discovery uses only the pinned site's drives and bounded folder enumeration, never unrestricted Graph search. Each eligible file repeats the established exact-site/drive/file metadata and If-Match content checks under current document authority. Initial limits are16 UTF-8 `.txt` documents,256 nodes,64 requests maximum and bounded transient content. PDF, DOCX and other formats are explicitly unsupported and not downloaded; answers disclose the unsupported count. Adding a supported file inside the existing approved site needs no per-file administrative grant. The app-only broker remains separate from external human/agent authorization. [Graph folder enumeration](https://learn.microsoft.com/en-us/graph/api/driveitem-list-children?view=graph-rest-1.0).

The executor owns one remote conversation per foreground session, gets fresh PF chat authority each turn, and posts the configured provider token only through the adapter's fresh-card flow. Reopening/unlocking discards the old association. Every answer rechecks authority; changed document content invalidates the existing context and requires a fresh chat. Context and excerpts are transient; no app/backend transcript is written. Microsoft-hosted transcripts/traces remain separate, and the owner-approved PoC trace exception still applies.
